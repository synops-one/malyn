# Security and data boundaries

Malyn is a single-user local tool. Its agent interface uses stdio MCP. General inference uses the local LM Studio SDK and explicitly excludes linked machines. Model and runtime downloads contact their upstream providers during explicit setup. The optional desktop UI and embedding processor have authenticated, loopback-only HTTP listeners with separate lifetimes.

Default job checks return a generic status note and artifact paths. They omit generated summary text and raw job errors; `returnMode: "summary"` explicitly opts into generated text. Reports and diagnostics remain on disk. Paths, filenames, content uploaded to a cloud chat and any artifacts subsequently retrieved by a frontier agent may reach its provider. There is no automatic secret redaction.

Shared loops are Markdown instructions with validated model/output metadata. Installing one does not run it. Supervising agents must keep collection instructions within the user's authorised scope; a loop cannot grant access or authorise external actions. Malyn's local model does not execute collection commands. Image input is restricted to explicitly supplied PNG/JPEG/WebP files within the task root, up to four files of 10 MiB each.

The `whisper` and `embeddings` processors are fixed application implementations, not executable commands supplied by loops. Model identity and input bounds are enforced. Runtime archives and weights are pinned with SHA-256; installation is explicit, and job startup verifies model/executable hashes. Whisper uses a pinned community Windows Vulkan build. See [component sources](docs/components.md) before installing. Neither processor accepts remote input URLs. Transcription retains a staged audio copy, transcript and diagnostics in its job directory; embeddings and source filenames remain in the local JSON artifact. The embedding server uses a random per-job API key and is stopped on completion or cooperative cancellation; the temporary key file is removed. A forcibly killed worker may leave a child process or staging files requiring local cleanup.

The model receives a task root and bounded text tools. It has no shell, browser, connector, source-editing or messaging tool. It writes new artifacts inside its job directory. Reads, listings and searches exclude dot-prefixed entries (including hidden application state), traversal, links/junctions and common credential filenames. This also excludes ordinary dotfiles and folders such as `.github` when encountered below the task root; stage explicitly selected content in a narrow input directory when needed. These are application checks, **not an operating-system sandbox**. They do not detect every secret and cannot protect against a hostile local user racing filesystem changes. Use `allowedRoots` and narrow task roots; never delegate a home directory or credential store.

Source content and model output are untrusted. A supervising agent must review citations and proposed patches and perform its own validation. Prompt injection can still influence a local model; instructions alone are not a security boundary.

Local requests, logs and artifacts remain on disk until the user removes them. They can contain sensitive data. Restrict access to the installation/config directory. Short results and any artifacts the supervisor reads enter that agent's context and may reach its cloud provider. Do not describe the entire workflow as offline or promise that no data leaves the machine.

Cancellation is cooperative. The worker forwards an abort signal and marks cancelled runs unfinished. If the runtime stops responding, inspect the recorded worker PID before terminating it. Never kill every Node or LM Studio process.

Report vulnerabilities privately through [GitHub private vulnerability reporting](https://github.com/synops-one/malyn/security/advisories/new). Do not put credentials or private logs into public issues. Release archives include source and dependency licenses; they exclude models, user configuration and job data.
# Local desktop control surface

Screenshot mode is explicitly opt-in and reads new clipboard images while the tray is running. It also sees images copied from other applications; the clipboard does not reliably distinguish screenshots. It ignores existing clipboard contents when enabled, never collects clipboard text and never takes timed screenshots. Captures and reports can contain sensitive material and persist in the configuration directory. Generic completion notifications omit image contents. Turning the mode off prevents future captures but does not erase retained data or cancel an already submitted job.

The optional admin UI is loopback-only and requires a per-session bearer token. It validates Host/Origin, rejects cross-site API and subresource requests (while allowing top-level navigation to the public HTML shell) and serves reports as plain text only after an explicit local request. The tray starts no HTTP listener until you open the UI. Session tokens, pause state and startup ownership records are per-user local state, excluded from release packages. Protect the configuration directory with normal user-profile permissions. Same-user processes are not isolated by this mechanism. See [desktop controls](docs/desktop.md).
